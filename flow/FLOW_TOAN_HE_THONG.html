Flow toàn bộ hệ thống

01 · Tổng quan và quan hệ dữ liệu

Web gọi API để thiết lập dữ liệu, tạo lượt đăng ký, mở buổi và xem kết quả. ESP32 đọc mẫu từ cảm biến rồi gửi request. Backend kiểm tra quyền, trạng thái và thời gian trước khi ghi MongoDB.

Lớp hành chính nhóm sinh viên qua classId. Lớp học phần gắn môn và giảng viên. Sinh viên tham gia lớp học phần qua bản ghi enrollment. Buổi học và ESP32 dùng chung roomId để backend tìm đúng phòng. ESP32 nhận lượt qua GET /devices/me/pending-registration trước khi gửi mẫu.

02 · Tài khoản và phiên đăng nhập

  1. Tạo tài khoản

    POST /users/create

    Gửi fullName, userName, password, role. Với role student, gửi thêm studentCode và classId. Kết quả trả ID tài khoản.

    201 · Tạo thành công. 400 · Dữ liệu sai. 409 · Trùng userName.

  2. Đăng nhập trên web

    POST /auth/signin

    Gửi userName và password. Backend kiểm tra mật khẩu, trả accessToken và đặt cookie refreshToken có chữ ký và HttpOnly.

    401 · Sai tài khoản hoặc mật khẩu.

  3. Gọi API được bảo vệ

    Authorization: Bearer <access-token>

    Backend xác minh token và gắn thông tin người dùng vào request. API tạo lượt đăng ký kiểm tra thêm vai trò teacher.

    401 · Token thiếu hoặc không hợp lệ. 403 · Sai vai trò ở route tạo lượt.

  4. Cấp lại token

    POST /auth/refresh-accessToken

    Trình duyệt gửi cookie refreshToken. Backend cấp accessToken mới và đặt lại cookie refreshToken.

    401 · Cookie thiếu hoặc token không hợp lệ.

  5. Đổi mật khẩu

    PATCH /users/updatePassword

    Gửi oldPassword và newPassword. Backend lấy ID người dùng từ access token.

    400 · Mật khẩu cũ sai. 404 · Không tìm thấy người dùng.

03 · Chuẩn bị dữ liệu học vụ và thiết bị

Nhánh lớp hành chính, môn học và phòng có thể chuẩn bị song song. Lưu ID trả về để nối tài nguyên ở bước sau.

  1. Tạo lớp hành chính

    POST /classes/create

    Gửi classCode và className. Dùng _id trả về làm classId khi tạo hoặc nhập sinh viên.

    409 · Trùng classCode.

  2. Nhập sinh viên theo lớp

    POST /users/:classId/import

    Gửi Excel qua multipart/form-data, trường file. Sheet đầu cần fullName và studentCode. userName hoặc password bỏ trống sẽ lấy studentCode. Backend gán role student, classId và băm mật khẩu.

    400 · Thiếu file, dữ liệu dòng hoặc classId sai. 404 · Không có lớp. 409 · Trùng mã sinh viên hoặc tên đăng nhập.

  3. Tạo môn học

    POST /courses/create

    Gửi courseCode và courseName. Lấy courseId từ _id của môn học.

    409 · Trùng courseCode.

  4. Tạo lớp học phần

    POST /sections/create

    Gửi sectionCode, courseId, teacherId, academicYear, term. teacherId thuộc tài khoản teacher, term thuộc 1, 2, 3.

    404 · Thiếu môn học hoặc giảng viên. 409 · Trùng sectionCode.

  5. Ghi danh sinh viên

    POST /enrollments/create

    Gửi sectionId, studentId, addedBy và tùy chọn addedAt. Cặp sectionId + studentId xác định sinh viên thuộc lớp học phần nào.

    404 · Thiếu tài nguyên tham chiếu. 409 · Đã ghi danh lớp này.

  6. Tạo phòng học

    POST /rooms/create

    Gửi roomCode, building, campus. Lấy roomId từ _id của phòng.

    409 · Trùng cặp roomCode và campus.

  7. Khai báo ESP32

    POST /devices/create

    Gửi deviceCode, deviceName, roomId, authSecret và tùy chọn status, lastSeenAt. Mặc định active. Backend băm secret. ESP32 dùng mã máy và secret ban đầu để xác thực.

    404 · Phòng không tồn tại. 409 · Trùng deviceCode.

04 · Đăng ký vân tay

Giảng viên tạo lượt

POST /fingerprint-registrations
Authorization: Bearer <teacher-token>
Content-Type: application/json

{
  "studentId": "<student-id>",
  "deviceId": "<device-object-id>",
  "fingerPosition": "rightIndex"
}

201 trả registrationId, studentId, deviceId, fingerPosition, status pending và expiresAt.

ESP32 nhận lượt rồi gửi mẫu

GET /devices/me/pending-registration
X-Device-Code: FP001
X-Device-Secret: <secret>

POST /fingerprints/create
X-Device-Code: FP001
X-Device-Secret: <secret>
Content-Type: application/json

{
  "registrationId": "<registration-id>",
  "templateData": "<sample>",
  "templateFormat": "ISO-19794-2",
  "algorithmVersion": "v1"
}

201 trả registrationId, fingerprintId và status completed. Backend lấy sinh viên và vị trí ngón từ lượt đăng ký. Gửi lại lượt hoàn tất của cùng máy sẽ nhận lại ID mẫu đã lưu nếu mẫu còn tồn tại.

05 · Lập lịch, mở và chốt điểm danh

  1. Lập lịch buổi học

    POST /sessions/create

    Gửi sectionId, roomId, startTime, endTime. Có thể gửi attendanceOpenTime và attendanceCloseTime. Status mặc định scheduled. Các mốc dùng ISO 8601.

    400 · Khoảng thời gian không hợp lệ. 404 · Thiếu phòng hoặc lớp học phần. 409 · Lớp học phần đã có buổi cùng startTime.

  2. Mở điểm danh

    PATCH /sessions/:id

    Gửi {"status":"open"}. Buổi phải cùng phòng với máy và giờ server phải nằm trong cửa sổ điểm danh. Thiếu mốc mở hoặc đóng thì dùng startTime hoặc endTime tương ứng.

    Chỉ chuyển trạng thái open chưa đủ nếu thời gian hiện tại ngoài cửa sổ.

  3. Xem bản ghi

    GET /attendance · GET /attendance/:id

    Web đọc kết quả theo bản ghi. Danh sách sắp theo receivedAt giảm dần và kèm thông tin sinh viên, buổi học.

    404 · Không tìm thấy ID bản ghi.

  4. Bổ sung điểm danh thủ công

    POST /attendance/create

    Gửi sessionId, studentId, status và method: manual. Có thể gửi checkInTime, deviceId, receivedAt. Trường checkInTime có thể bỏ trống hoặc null khi vắng.

    409 · Cặp sessionId và studentId đã có kết quả.

  5. Sửa hoặc xóa bản ghi

    PATCH /attendance/:id · DELETE /attendance/:id

    PATCH có thể đổi status, method, thời gian và thông tin tham chiếu. Các trạng thái hợp lệ là present, late, absent.

    404 · Không tìm thấy bản ghi hoặc tham chiếu. 409 · Trùng cặp buổi và sinh viên khi sửa.

  6. Đóng hoặc hủy buổi

    PATCH /sessions/:id

    Gửi status: closed hoặc cancelled theo tình huống. API check-in chỉ tìm buổi open.

    Nếu phòng hết buổi mở hợp lệ, request check-in nhận 400.

06 · ESP32 điểm danh

Request từ ESP32

POST /attendance/device-check-in
Content-Type: application/json

{
  "deviceCode": "FP001",
  "authSecret": "<secret>",
  "templateData": "<sample>",
  "timestamp": "<ISO-8601 hiện tại>"
}

Kết quả và mốc thời gian

201 trả bản ghi gồm sessionId, studentId, status, checkInTime, deviceId, method và receivedAt. Với luồng ESP32, deviceId lưu mã máy, method là fingerprint và hai mốc thời gian lấy theo giờ server.

Backend xác minh chuỗi mẫu bằng hash đã lưu. Hai lần quét cùng ngón nhưng sinh chuỗi khác nhau sẽ dẫn đến 404. Chưa kiểm chứng trên ESP32 thật.

07 · Danh mục 51 API

URL mặc định http://localhost:3000. ESP32 dùng địa chỉ backend có thể truy cập qua mạng. Bearer là Authorization: Bearer <access-token>. Header ESP32 gồm X-Device-Code và X-Device-Secret. Body ESP32 gửi mã máy và secret trong JSON. Tham số :id hoặc :classId là ID tài nguyên.

Khác biệt giữa mã nguồn và tài liệu API
  • POST /users/create được đánh dấu công khai trong controller dù tài liệu users mô tả Bearer.
  • Hai API auth trả statusCode: 200 trong body. Controller dùng @Post và chưa đặt @HttpCode(200), nên HTTP status theo mặc định của NestJS là 201.
  • PATCH /fingerprints/:id hiện khai báo lại studentId và fingerPosition mà thiếu IsOptional. Request chỉ đổi status có thể nhận 400.
